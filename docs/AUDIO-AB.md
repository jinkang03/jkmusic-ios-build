# 音效整链离线对拍（iOS vs Mac）

日期：2026-11-24 · 版本：1.4.51 之后

## 目的

用同一段素材、同一组参数，分别跑 Mac 端（Chrome / Web Audio）和 iOS 端（MTAudioProcessingTap 里的
Swift DSP），比较电平、频段能量和波形，确认「效果一致」不是靠耳朵猜。

## 方法

| 项 | 内容 |
|---|---|
| 素材 | 12s 立体声 44.1k：左右不同种子的粉噪 + 100Hz / 1kHz 正弦 + 每 2s 一个瞬态脉冲，RMS ≈ -18.6 dBFS |
| 参数 | EQ = 摇滚预设（7,6,2,1,-3,-4,2,1,4,5）；IR = `bright-hall.wav`（4 声道）；原始增益 180%；环境增益 240%；变调 1.00x；环绕关闭 |
| Mac 侧 | Chrome headless + `OfflineAudioContext`，节点链与 Mac 端完全一致（10×BiquadFilter → Gain(dry) / Convolver → Gain(wet) → DynamicsCompressor → destination），渲染结果导出 WAV |
| iOS 侧 | 同一份 WAV 输入，调用 `SoundEffectProcessor.renderOffline`（与 tap 完全同一条链），导出 WAV |
| 对比 | numpy：整体 RMS、10 个倍频程频段能量、FFT 互相关对齐后的波形相关与相对误差 |

复现脚本（临时目录）：`/tmp/ab/render2.html`（Chrome 渲染）、`/tmp/ab/drive.mjs`（CDP 驱动）、
`/tmp/ab/swift/main.swift`（Swift 离线渲染）、`/tmp/ab` 下的对比脚本。

## 结果

### 整链（干 + 湿）

| 指标 | 结果 |
|---|---|
| 总电平 | MAC L -10.53 / R -12.65 dBFS；SWIFT L -10.83 / R -12.95 dBFS（差 -0.30 dB） |
| 10 个频段（31Hz–16kHz） | 差值全部在 **-0.28 ~ -0.31 dB**，形状完全一致 |
| 波形对齐 | lag = 0 样本；相关系数 **0.9992 / 0.9991** |
| 相对误差 | 5.15% / 5.35%（主要来自那 -0.3 dB 的常数差） |

### 拆分定位

| 路径 | MAC | SWIFT | 差 |
|---|---|---|---|
| 湿声（干=0，湿=1） | L -25.92 / R -25.14 | L -25.90 / R -25.14 | **+0.02 / 0.00 dB** |
| 干声（干=1.8，湿=0） | L -10.51 / R -13.04 | L -10.80 / R -13.33 | -0.29 / -0.29 dB |

→ 卷积、IR 归一化、4 声道真立体声、EQ 全部一致；差异只在压缩器。

### 压缩器静态曲线

1kHz 稳态正弦（RMS -17.0 dBFS）分别过两边的压缩器：

| | 输出 RMS |
|---|---|
| MAC | -13.202 dBFS |
| SWIFT | -13.212 dBFS |

差 **0.01 dB** → 静态曲线一致；0.28 dB 的差是噪声/瞬态下的动态差异（attack/release 细节），
属于听不出来的量级。

## 结论

- 湿声（混响）逐样本级一致（0.02 dB）
- EQ 频响逐频段一致（最大 0.31 dB 的常数偏移来自压缩器）
- 压缩器静态曲线 0.01 dB，节目素材 0.28 dB
- 波形相关 0.9992，无相位/延迟错位

## 已知未覆盖

- 变调（相位声码器）未纳入整链对拍：Mac 侧需要额外加载 AudioWorklet，且已用频率测试单独验证
  （1.0x/1.5x/0.5x/1.2x/0.8x 的输出峰值与理论一致）
- 3D 环绕未纳入整链对拍：位置随时间是连续变化的，已用固定角度的增益公式单测验证
