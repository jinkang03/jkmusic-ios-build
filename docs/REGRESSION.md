# 回归清单（每次构建前过一遍）

> 目的：防止「修好的问题被后续改动丢掉」。新增修复时在对应版本下追加一行。
> 每项写清「现象 / 验证方式」，验证方式要能一条命令或一次截图完成。

## 1.4.35

| # | 现象 | 验证方式 |
|---|---|---|
| 1 | 点歌后 0:00 卡死，既不报错也不换源 | 把源地址换成挂死地址（`badurl&url=http://10.255.255.1/x.mp3`）→ 8s 后出现 `看门狗超时：8s 未就绪` + `换源成功` |
| 2 | 起播看门狗从来不生效 | 日志必须出现 `看门狗超时`（守卫改用 `nativeQueue.token`，不再比已被清空的 `trackSourceLoadingStore`） |
| 3 | 挂死地址被当成可用地址 | `verifyMediaUrl` 3s 无响应（AbortError）→ 判死，脚本池换下一个 |
| 4 | 停住提示后每 12s 又弹一次 | 停住后再等 25s，`换源`/`看门狗` 计数不再增加 |
| 5 | 正常播放被看门狗误杀 | 连播 6 首：pos 8.5-10.4（12s 窗口），`看门狗超时` 计数为 0 |

## 构建前自检

```bash
./node_modules/.bin/tsc --noEmit | grep "error TS"     # 必须为空
./node_modules/.bin/eslint <改动的文件> --quiet         # 0 error
./scripts/dev-sim.sh                                   # 构建 + 截图
```

出包后核对：

```bash
./scripts/build-ios.sh
# 产物断言：widget appex / NSSupportsLiveActivities / 版本号
./scripts/sync-latest-ipa.sh   # build-ios.sh 已内置
```
