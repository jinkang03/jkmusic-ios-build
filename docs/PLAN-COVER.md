# 歌单封面 + 更新歌单（实施规划，待确认）

版本目标：1.4.47（build 71），分 3 批。

---

## 0. 需求拆解

| 需求 | 落地含义 |
|---|---|
| 导入歌单 / 手动导入歌单显示封面 | 「我的列表」每一行的 56×56 图标从固定心形改为真实封面 |
| 支持更新的歌单（含链接） | 有来源链接（平台 + 歌单 id）的歌单才有「更新歌单」；手动创建的不显示 |
| 更新歌曲时同步更新封面 | 更新时顺带拉平台歌单信息，刷新封面（自定义封面不覆盖） |
| 二级菜单支持自定义封面 | 长按菜单加「设置封面 / 恢复默认封面」 |

## 1. 用户看到的样子

### 1.1 我的列表（一级页面）

每行左侧 56×56 圆角图标：

| 歌单类型 | 图标显示 |
|---|---|
| 平台导入（QQ / 酷我 / 酷狗 / 网易云） | 平台歌单封面 |
| 平台导入 + 用户设过自定义封面 | 自定义封面（优先） |
| 手动创建 + 设过自定义封面 | 自定义封面 |
| 手动创建 + 没设过 | 第一首歌的专辑封面（列表为空则心形） |
| 封面加载失败 / 地址失效 | 自动退回心形，不出现空白或裂图 |
| 试听列表 / 我的收藏 | 心形（内置列表，不变） |

- 图标样式、行高、右侧箭头都不变，只是把心形换成图
- 不加「已自定义」角标，保持干净
- 手动创建的歌单没有平台封面，用第一首歌的专辑封面顶上；用户换过封面后不再跟随

### 1.2 长按二级菜单

现在：`更新歌单 / 删除歌单 / 取消`

改后（按条件显示，最多 5 项）：

| 菜单项 | 出现条件 |
|---|---|
| 设置封面 / 更换封面 | 所有用户歌单（已设过则文案变「更换封面」） |
| 恢复默认封面 | 仅当该歌单有自定义封面 |
| 更新歌单 | 仅有来源链接的歌单（source + sourceListId 可解析） |
| 删除歌单 | 所有用户歌单 |
| 取消 | 始终 |

- 手动创建的歌单长按：`设置封面 / 删除歌单 / 取消`（没有更新项，不做灰色假按钮）
- 试听列表 / 我的收藏长按：仍然提示「内置列表不能删除」，不提供改封面

### 1.3 设置封面

1. 长按 → 设置封面
2. 系统相册（可裁剪，固定 1:1）
3. 选完立即生效，返回列表已经换图（不需要重启、不需要手动刷新）
4. 图片复制进 App 沙盒，相册里的原图删了也不影响
5. 权限被拒：「需要相册权限才能设置封面」
6. 保存失败：「设置封面失败」，原封面保持

### 1.4 恢复默认封面

- 删除自定义封面 → 回到平台封面；手动创建的歌单回到心形
- 平台封面也没有（老数据没更新过）→ 心形

### 1.5 更新歌单

点「更新歌单」：

1. Toast：「正在更新「XX」…」
2. 拉平台全部歌曲（现有逻辑：最多 20 页 / 重试 3 次 / tx 兜底接口）
3. 歌曲整体覆盖
4. **同时**刷新封面为平台最新封面（仅当没有自定义封面）
5. 成功：「已更新」「「XX」共 N 首」
6. 失败：「更新失败」+ 原因（沿用现有文案）
7. 平台返回空 → 不动本地数据（现有保护保留）

### 1.6 导入歌单（链接）

- 导入完成，「我的列表」直接显示平台封面
- 之前导入的老歌单没有封面字段 → 第一次「更新歌单」后自动补上

### 1.7 手动创建歌单

- 「导入/创建歌单」页的「选择封面」现在真的生效（当前选了会被丢掉）
- 不选 → 用第一首歌的专辑封面；列表还没有歌时显示心形
- 创建后仍可长按更换

## 2. 数据模型

```ts
export interface JkUserList {
  id: string
  name: string
  source?: string            // tx | kw | kg | wy | mg
  sourceListId?: string      // 平台歌单 id / 分享链接
  locationUpdateTime?: number
  list: JKMusic[]

  /** 平台封面地址（导入/更新时写入；http 自动转 https） */
  coverUrl?: string
  /** 自定义封面：Documents/covers/ 下的文件名（不是绝对路径） */
  coverFile?: string
  /** 封面最近更新时间（换图时更新，给缓存兜底） */
  coverUpdatedAt?: number
}
```

- 老数据没有这三个字段：读取时按空处理，不需要迁移
- `createUserList(name, opts?: { coverFile?: string })` 扩展一个可选参数
- `renameUserList` / `setUserLists` 逻辑不变

### 封面优先级

```
coverFile（自定义） → coverUrl（平台） → 第一首歌的专辑封面 → 心形占位
```

第一首歌封面只对「没有平台封面」的歌单生效（典型是手动创建）。
取字段顺序：`meta.picUrl` → `meta.img` → `meta.artwork` → `meta.pic`，同样 http→https。
用户设过自定义封面后，封面不再跟随首曲变化。

## 3. 工程细节

### 3.1 文件存储

| 项 | 方案 |
|---|---|
| 目录 | `Documents/covers/`（首次使用自动创建） |
| 文件名 | `list-<listId>-<时间戳>.jpg`，每次换图唯一 |
| 为什么不用固定名 | expo-image 会按 URI 缓存，固定名会出现「提示成功但界面还是旧图」（壁纸踩过） |
| 旧文件 | 换图 / 恢复默认 / 删除歌单时删除 |
| 读取 | `getCoverUri(file)` = `documentDirectory + covers/ + file` |
| 备份 | `.lxmc` 只带 `coverFile` / `coverUrl` 字段，不带图片本体；恢复后文件不存在 → 自动回退平台封面或心形，不报错 |

### 3.2 取平台封面

| 来源 | 字段 | 备注 |
|---|---|---|
| tx | `info.img` | `songList.getListDetail` 已返回 |
| tx 兜底（fcg_v8_playlist_cp） | `resp.artwork` | 当前 `getSongListDetail` 兜底分支返回 `info: {}`，需补 `info: { name, img }` |
| kw | `info.img` | 已返回 |
| kg | `info.img` | 已返回（gcid 路径同样有） |
| wy | `info.img` | 已返回 |
| mg | 暂无 | 显示心形，不阻塞 |

统一处理：
- `http://` → `https://`（iOS ATS 会拦 http）
- 空串 / 非 http(s) → 不写入
- 写库前 trim

### 3.3 改动文件清单

| 文件 | 改动 |

### 3.4 兼容与边界

- 平台封面 URL 失效 → `onError` 回退心形，不缓存失败状态（下次进入重试）
- 更新歌单时平台没给封面 → 保留旧 `coverUrl`
- 用户改过封面后更新歌单 → 自定义封面不动
- 删除歌单 → 先删封面文件再删记录，失败不阻塞删除
- 备份恢复 → 字段随 JSON 走，文件缺失不报错
- 内置列表 → 不写 cover 字段，行为不变

## 4. 使用规则（可写进说明）

1. 只有带来源链接的歌单能「更新歌单」；手动创建的歌单没有这一项
2. 自定义封面优先于平台封面；「更新歌单」不会覆盖自定义封面
3. 「恢复默认封面」= 删除自定义封面，回到平台封面；没有平台封面则回到第一首歌封面（空列表回心形）
4. 封面只用于「我的列表」列表展示，不影响播放页、锁屏、下载页
5. 试听列表 / 我的收藏不支持自定义封面
6. 手动创建的歌单没设封面时跟随第一首歌；删除歌曲/换歌后封面可能变化，属预期
